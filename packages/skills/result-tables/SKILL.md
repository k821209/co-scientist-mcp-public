# /result-tables

**Triggers:** a second table of the same quantity is about to be added; a
number is about to be typed into a table rather than generated; "which table
is this number from"; "표에 있는 숫자랑 본문 숫자가 다른데"; before
`prepare_export` on any paper that reports one metric under several choices.

## The failure this prevents

One quantity — classification accuracy — under four choices (method, withheld
material, eligible classes, coarse-vs-fine agreement) is about twenty numbers
that all read as "NN.NN%". Spread over eight tables, nothing in a table said
which crossing its numbers belonged to, and every numerical error in that
project had the same shape: **quoting one crossing's number while describing
another crossing's question.** A pooled value computed over six files instead
of five (a 20-epoch variant sat in the same directory with the same columns
and a glob picked it up) reached three tables and a figure panel. A column
with no script behind it reproduced when re-derived, but nothing on disk could
have shown that. A baseline was reported under two conditions in two tables
with no label saying so. "The baseline beats the model" was written from a
2.46-point pooled difference against a fold-level interval of −8.2 to +10.0
that stood in a neighbouring table.

The first grid ended the confusion for the method it covered. It did not end
the generating errors: two intervals were typed into the grid that had not
been computed — into the table whose purpose was to stop exactly that. The
grid fixes reading; rule 2 fixes generating; rule 3 makes a wrong comparison
contradict the table instead of merely being absent from it.

## The three rules

**1. One grid per quantity, with the choices as columns.** Not one table per
experiment. Every row is a full crossing of the choices, and every number
quoted in the body is one cell of it. Per-class and per-fold tables are
breakdowns of a named row and say so in their caption ("breakdown of Table 2,
row 3"), never independent results.

**2. The grid is generated by a script from saved per-item outputs, not
typed.** A number with no per-item file behind it is the six-files-not-five
case waiting to happen. Two sub-rules, both earned: the script names its
expected inputs explicitly and **fails on an unexpected file rather than
skipping it** (a directory glob is how the stray variant got in); and a value
that cannot be regenerated is **marked in the table as held** (a dagger and a
one-line note), so it is not indistinguishable from a computed one. Record the
script as the table's provenance — `add_table` / `update_table` take
`source_analysis`, `source_runs` and `varies` for this, and
`compare_run_params` then lists every way the rows differ that the table did
not declare.

**3. The grid carries a resolvability block.** For any quantity whose sampling
unit is coarser than the row count (folds, studies, seeds), a short table of
paired differences with their interval over that unit, and one sentence naming
what the experiment cannot distinguish. The shape: "four methods land between
64.6% and 69.0%; every pairwise interval crosses zero; the experiment does not
order them." A claim that one method beats another must be able to point at a
row of this block whose interval excludes zero.

## The check the author cannot run by eye

`lint_results_grid(slug, table_number=N)` reads every accuracy-like number in
the paper's sections and looks each up in the cells of the grid: a number that
matches **no cell** is either typed, stale, or from a breakdown that should
have cited its row; one that matches **more than one cell** cannot be tied to
a crossing from the sentence alone and needs the crossing named in the
sentence. Run it after every rewrite of Results and Discussion; the return
value names the sentence, the number and the cells. Read the docstring for
what counts as a number and how to widen it.

Its scope is the body against one designated grid. It does not verify that the
grid's own numbers are right — that is rule 2's script, and `/analysis-audit`
if the per-item outputs are in doubt.

## Also

- The caption names the quantity and the choices, once; the numbers stay in
  the table (`/paper-writing` on captions).
- A paper with two quantities has two grids. A grid with a choice that never
  varies has one column too many.
